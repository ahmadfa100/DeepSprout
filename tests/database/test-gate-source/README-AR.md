# DeepSprout — بوابة اختبار قاعدة البيانات M1

**التاريخ:** 2026-11-01  
**الحالة:** حزمة بدء واختبارات هيكلية؛ **ليست** دليل نجاح SQL Server أو اعتمادًا للإنتاج.

## ما تحقق الآن

- القاموس v2.1 المرفق في المحادثة يحتوي 129 صف جدول.
- اختبار `03-reproducible-canonical-dictionary-check.py` قرأ القاموس المحدد مباشرة وتعرّف على الجداول الـ129 والـ19 المطلوبة للشريحة الأولى.
- النتيجة الحالية: **12 حقلاً مطلوبًا غير مُعلن في 11 جدولًا من M1**. القائمة الدقيقة في `static-canonical-current-results.csv`.
- لم يكن لدينا وصول إلى خادم SQL Server الخاص بالمستخدم. **لم يُنفّذ أي أمر SQL** من هذه الحزمة على جهازه بعد.
- SQL الخاص بالنسخة المصححة ذات 19 جدولًا **غير متاح ضمن الملفات المستلمة**، ولذلك لم ننشئ Migration أو نزعم نجاحها.

## التشغيل على جهازك باستخدام SSMS — بالترتيب

1. افتح `00-environment-readonly.sql` في SSMS واتصل بخادم SQL Server الذي ظهر في صورتك. شغّله. لا يغيّر أي قاعدة. احتفظ بنتيجتي الاستعلام وصورة/نص الإصدار.
2. راجع `01-create-isolated-validation-db.sql` ثم شغّله إذا أردت إنشاء قاعدة مستقلة باسم `DeepSprout_Validation`. السكربت لا يستخدم ولا يحذف `CourseHubDB`؛ ينشئ قاعدة جديدة فقط إذا لم تكن موجودة. إذا كانت موجودة فلا يعدّلها.
3. **لا تشغّل DDL القديم v2 باعتباره تصميمًا معتمدًا.** أولًا أصلح القاموس ذو 19 جدولًا، ثم أنشئ EF Core Entities/Configurations وMigration لـM1 من النسخة المصححة، وافحص SQL الناتج وطبقه فقط على `DeepSprout_Validation`.
4. بعد ظهور الجداول، شغّل `02-schema-contract-readonly.sql`. يعرض `PASS/FAIL` لوجود الـ19 جدولًا، ولـ21 عمودًا حرجًا، وللفهرس الفريد المشروط، ولعلاقتين مركبتين حرجتين. لا يغيّر البيانات.
5. بعد نجاح الاختبارات الهيكلية، نفّذ اختبارات CRUD السلبية والعمليات والتزامن الواردة في `04-acceptance-matrix.md` بواسطة اختبارات تكامل C# أو T-SQL متخصصة تُشتق من إجراءات M1 الحقيقية. **لا يمكن كتابة اختبارات قابلة للتشغيل لهذه العمليات قبل معرفة DDL وواجهات المعاملات النهائية.**
6. احفظ نسخة من نتائج كل اختبار، والـMigration المستخدمة، وإصدار الخادم، وأرقام أخطاء SQL، ووقت التشغيل؛ لا نستبدل دليلًا فاشلًا بادعاء نجاح.

## سبب الفصل بين الاختبارات

- **Static contract test:** يقرأ Markdown ليرصد أعمدة ناقصة. فشله لا يعني أن SQL Server نفذ شيئًا.
- **SQL schema test:** يفحص كتالوج SQL Server بعد إنشاء الجداول. نجاحه لا يثبت أن أوامر القبول والانسحاب تعمل.
- **Negative / transactional test:** يحاول حالات بيانات خاطئة ويتوقع الرفض بسبب محدد.
- **Two-connection concurrency:** يحاول عمليتين متعارضتين في وقت واحد ويثبت فشل إحداهما دون فساد بيانات.
- **Authorization / privacy:** ينفذ أدوارًا مخولة وغير مخولة، بما فيها سحب صلاحيات المشرف وقراءة الملفات.

## سياسة التسليم

- الـ19 جدولًا بوابة M1، والـ129 جرد النطاق الكامل؛ لا نطبق 129 جدولًا دفعة واحدة.
- Clean Architecture وDTO وEF Core Migrations وSQL Server لا تتعارض. نراجع Migration SQL ونتحقق على SQL Server الفعلي.
- لا نستخدم `EnsureCreated()` لتأسيس قاعدة مخطط لإدارته عبر EF Migrations.
- **لا تعديل أو حذف لـCourseHubDB ولا لأي قاعدة مستخدمة في مشروع آخر.**

انظر `04-acceptance-matrix.md` لمعايير القبول وأرقام الحالات، و`05-owner-decisions-handoff.md` للتوثيق اللاحق لدى Codex دون إرسال prompt جديد الآن.
