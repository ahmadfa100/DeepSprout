# 11 — Transactions and concurrency

Use SQL Server transactions for every authoritative transition, with a single idempotency key per client command and an `AuditEvent`/`OutboxMessage` inserted before commit. Server time decides windows. `READ COMMITTED` plus explicit `UPDLOCK,HOLDLOCK` on the owner/slot/appointment rows is the default for capacity; `SERIALIZABLE` is an alternative for a small hot allocation query if lock behavior is easier to prove. RowVersion handles stale edits to one root; unique indexes prevent duplicate claims. Retry only recognized transient conflicts after rereading, with a bounded count.

| Operation | Locked/check set and atomic write | Race/duplicate failure |
|---|---|
| Initiative application approval | Lock Initiative and free `InitiativeSeat`, recheck status/eligibility/terms and actor grant, create Membership and point seat, mark Application Accepted, audit/outbox. | Two Rep/Supervisor approvals of same Application return same result by idempotency/unique `(InitiativeId,PersonId)`; 136th has no slot and remains queued/pending. |
| Initiative offer and suspension | Lock Initiative/slot/application; valid offer holds slot until expiry; accepted converts holder to membership. Suspend leaves occupied slot under interim default. | Expiry/accept compete under same owner lock; exactly one wins. No silent seat release from suspension. |
| Active Supervisor acceptance | Lock Initiative, count active Supervisor appointments under same lock, verify invitation/email/expiry, insert Active appointment, mark invitation accepted. | Fourth active refused; pending invites do not count. Revocation/acceptance serialized. |
| Session registration | Lock `SessionCapacityPool` and free `SessionSeat`, verify published revision/mode/eligibility; insert Registration and slot holder. | Same person/session unique; online and in-person pools isolated. |
| Provider booking and waitlist | Lock Experience and free `ExperienceSeat` for direct confirmation; if full, create Queued Booking. Cancellation clears slot and offers to next eligible queue item in same transaction or idempotent job. | Held+confirmed≤slots; duplicate booking unique; queue ordering is configurable policy. |
| Offer accept/decline/expire | Lock Experience, offer, slot, booking; compare server time and state; accepted replaces offer holder with booking holder; declined/expired releases and reoffers. | Expired acceptance fails; concurrent job and participant cannot both allocate or overbook. |
| Invitation acceptance | Lock invitation/Person email verification and target owner; verify token hash, email and active policy; create exact membership/appointment once; mark used. | Wrong email/replay/revoke cannot grant. Existing Person reused; no merge on unverified email. |
| Submission review | Lock Submission/current Attempt and reviewer grant; insert immutable ReviewDecision, advance status; publish approved EvidenceEvent once. | Concurrent reviewers cannot both finalize same version; correction supersedes decision and compensates reward. |
| Attendance/excuse | Lock Registration/Attendance and appointment; validate method/window/nonce. Record factual status and event; correction appends before/after/reason. Excuse recommendation/final decision separately checks roles. | QR replay is idempotent; revoked Supervisor denied; accepted excuse never changes Absent to Present. |
| Reward issuance | Unique EvidenceEvent source/version; evaluate published policy; insert Personal/Group Grant entries under unique filtered indexes; outbox projection update. | Replayed event hits unique key/no-op; linked owners reuse event; invalidation yields one attributed Reversal. |
| Entitlement change/use | Lock allocation/subscription version, check grant and limit, append UsageLedger with source key, audit/outbox. | No oversubscription of feature quota; subscription never creates resource authority. |

**Failure semantics:** all validation failures leave authoritative state unchanged. A committed mutation with failed notification remains committed and the outbox retries; UI can show Pending delivery. A projection failure is rebuilt from originals. Deadlocks retry a whole transaction, never only the final update. Use chaos/concurrency tests with independent DbContexts and real SQL Server, not an EF InMemory provider, to prove 135/3 and seat/offer cases.
