# 16 — Dependency-ordered implementation roadmap (future work only)

This is a plan, **not authorization to implement during this documentation task**. Each slice ends with an API/SQL Server integration test, a permission negative test, a replay test where relevant, and a source-to-UI walkthrough. Prefer an expand/backfill/switch/contract rollout over a big-bang browser-data import.

1. **Contracts and foundation:** approve resource/Person public IDs, error/idempotency contract, privacy classes, status vocabulary and policy-version conventions. Create SQL Server project, least-privilege principals, backup/restore and outbox/audit infrastructure; first EF migration for `iam`, `ops` and immutable reference codes. Verify one Person with two scoped grants.
2. **Identity and grants:** secure password/OTP/recovery, verified email, invitations, Admin provisioning and resource-scoped authorization handlers. Implement revocation invalidation and request/selected-grant audit. Test E/F/H negative cases before exposing partner data.
3. **Core personal journey:** instrument versions/attempts and resumable onboarding; Recovery Journey/Cycle/Revisions; approved Activity definitions/attempts/routine; Shield configuration and browser-evidence contract. Create separate source-labeled Insights queries. Validate A without fabricated scores or usage.
4. **Institution ownership and admission:** verification/Representative, Initiative revisions/publication, Application/Membership/Seat/Offer, active Supervisor appointments, Groups/placements. Implement locked approval and 135/3 race tests. Expose original Initiative/Application IDs to regular Individual and owner projections; validate B through admission.
5. **Shared work and sessions:** Group Coach assignments, Assignment/Recipient/Submission/Review/report; Session mode seats/registration, active Supervisor attendance, corrections, excuses and completion. Validate B/C/G and authorship across transfer. Add identified forms/competition only behind approved response/privacy policies.
6. **Provider and partnerships:** Provider verification/ownership, Experience terms/slots/booking/waitlist/offer jobs, appointments/attendance/camp completion; accepted links to Initiative with data-scope contract. Validate D and concurrent offer expiry/acceptance; never copy booking ownership.
7. **Evidence/reward/reporting:** original source events, rule versions, personal/group ledgers and projections, compensation, five-domain Insights and Coach→Supervisor→Representative reporting. Replay and correction tests A–G; verify four-tree and GroupGarden ownership rules.
8. **Governance, Community and entitlements:** one Admin capability map, catalog/CMS/moderation releases, notices/delivery, safe Community scope. Introduce versioned subscription entitlements only after commercial approval; billing integration is a separate reviewed slice.
9. **Migration and rollout:** inventory `deepsprout-ecosystem-demo-v1`, `deepsprout-account-changes-v1:*`, `deepsprout-user-v1`, legacy Admin keys and fixture provenance. Export backups, dry-run alias/identity mapping, quarantine ambiguous/unverified records, preserve timestamps/source labels and historical versions. Never silently import demo prices/fictional people as production. Dual-read compatibility with explicit cutover and reconciliation counts; rollback restores old read path and backups, not destructive deletion. Exercise all A–H scenarios on a staging copy, then monitor outbox lag, conflicts, auth denials and capacity invariants after release.

**First implementation slice:** identity/authorization/audit plus one original Initiative publication/application path, because every later cross-workspace workflow depends on stable Person/resource IDs and the same admission fact. The browser demo can remain as reference while the production API is introduced incrementally. No existing application code, migration or database was changed for this package.
