# DeepSprout v5 — SQL Server scripts (approved 58-table design, v5-lean-2)

| File | Purpose |
|---|---|
| `DeepSprout-v5-FULL-Database.sql` | Generated. Creates `DeepSprout_V5_Demo` if missing, then the 58 tables, then DEMO ONLY data, then demonstration queries. Never drops anything |
| `DeepSprout-v5-NEGATIVE-TESTS.sql` | 40 tests, each rolled back: 26 original constraint tests plus T27–T40 for Onboarding 2.0 and v4.1. The last grid shows PASS/FAIL |
| `adopt-v5-baseline.sql` | Records EF migration `V5Baseline` as applied in an existing v5-lean-1 database after verifying its schema fingerprint. Changes no table or row |
| `DeepSprout-v5-UPGRADE-lean1-to-lean2.sql` | Generated by `dotnet ef migrations script --idempotent` from `V5Lean2Onboarding2AndV41`, for review before upgrading `DeepSprout_V5_Demo` |
| `SQL-VALIDATION-RESULTS.md` | What was executed and the actual outcomes |
| `AUDIT-RESPONSE.md` | Response to the 5 November audit of the 57-table draft (historical rationale) |

## Run it (SSMS)

1. Connect to SQL Server 2019 or later where you may create databases.
2. Open `DeepSprout-v5-FULL-Database.sql` and press **F5**. No editing is needed.
3. Run the `PART 4 — DEMONSTRATION QUERIES` blocks one at a time while presenting.
4. Optional: run `DeepSprout-v5-NEGATIVE-TESTS.sql`.

If `DeepSprout_V5_Demo` already holds a v5 schema the script only runs the queries; if the database holds other tables it stops touching it. An existing **v5-lean-1** `DeepSprout_V5_Demo` is not upgraded by this script: adopt it with `adopt-v5-baseline.sql`, then apply the EF migration (see [EF Core adoption](../../efcore-v5-adoption.md)).

Command line: `sqlcmd -S <server> -E -C -b -i DeepSprout-v5-FULL-Database.sql`

## What is in the database

58 tables, 18 schemas, 146 foreign keys, filtered unique indexes ("one live X"), CHECK constraints including `ISJSON` on every JSON column, 0 triggers, 0 procedures. History tables are insert-only for the application role `ds_app`; the retired tables `coach.CoachProgram` and `partnership.PartnershipLink` are read-only for it. See the [database index](../../README.md) for the table list.

## Demo data

All fictional, DEMO ONLY, `example.com` e-mails, no passwords (`PasswordHash` is NULL). It covers an activated Individual with Lab history, a recovery plan, practices, routines and Shield; a new Individual at Home (Journey Level 1, six versioned answers, an unactivated Week 1 plan, no Lab attempt); students in every membership status; a Coach, a Representative and an Initiative Supervisor; a published initiative with a waiting list; groups, tasks, submissions and reviews; sessions, attendance and an excuse; an Institution-owned outdoor camp with a cohort, bookings and an incident; forms, a survey response and a judged competition entry; community content; notifications, outbox rows and audit history. One historical independent program and one partnership remain as read-only history.

## Known limitations

- Concurrency (seat races, supervisor cap, duplicate submissions) relies on application services that do not exist yet.
- Cross-owner consistency (for example attendance person versus registration person) is an application rule (negative test T26).
- No page of the web application uses this database yet.
- Regeneration: from `../generator`, `node build.mjs`, `node emit-sql.mjs`, `node emit-efcore.mjs`.
