## قرارات معلقة وحدود الاعتماد

- قاموس الشراكة يسرد `Requested/Accepted/Declined/Ended` لكنه يشير أيضاً إلى `Active` في فهرس الرابط الحالي. يدعم المخطط الحالات الخمس ويمنع ازدواج الرابط الحالي، لكن انتقال `Accepted → Active` التشغيلي يحتاج اعتماد المالك.
- لم تُعتمد بعد مصفوفة أنواع أسئلة النماذج والمدى المسموح لدرجات المسابقات. نُفذت ملكية النسخة والسؤال والمعيار وتعددية الإجابة، وبقيت قواعد النوع والمدى **NOT EXECUTED**.
- سياسات عمر/ولي الأمر واحتفاظ OTP، وإذن موارد SecureFile واحتفاظها، واحتفاظ حوادث Provider، ومصدر فوترة Commercial وصلاحية تخصيص المستفيد وتعبئة الفترات التاريخية تحتاج قرارات قبل الإنتاج. الحقول التاريخية المستعادة تقبل NULL عمداً حتى تُعتمد تعبئة صحيحة.
- أظهرت تجارب التطوير الأولية فشلاً في تأكيد حالتين تجاريتين بسبب ترتيب بيانات الاختبار؛ صُححت العينة وأعيدت كل المجموعات بنتيجة 330/0. فشل السكربت الخام المتكرر بسبب صيغة دفعات SQL Server، ثم نجح السكربت المحول. احتُفظ بأدلة المحاولات السابقة؛ لا تُقدَّم على أنها اجتياز من المحاولة الأولى.

**القرار التنفيذي:** قاعدة التحقق جاهزة للانتقال إلى تطوير Onion Architecture backend وAPI بعد حسم السياسات أعلاه. نتيجة قاعدة البيانات لا تمنح اعتماد إطلاق إنتاج أو اعتماد أمن API. لم تُنفذ عمليات حذف قواعد أو تعديل `CourseHubDB` أو قواعد أخرى.
