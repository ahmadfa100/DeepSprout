# 03 — Bounded contexts and ownership

Contexts are module boundaries inside **one modular monolith**, not mandated microservices/databases. Each row gives purpose; actors; aggregate roots (bold); owned records/value objects; events; invariants/transactions; privacy/integration. An aggregate is sized around a command that needs one consistency decision, not around a UI page. Cross-aggregate associations are IDs.

| Context | Purpose, actors, aggregates and rules | Events, dependency and privacy |
|---|---|---|
| Identity & Access | Person signs in and changes capabilities. **Person** owns verified emails/credential state; **OtpChallenge** owns one verification use; **GlobalGrant** is internal Admin authority. Person ID is stable during upgrade. | `EmailVerified`, `OtpUsed`, `GlobalGrantRevoked`; owner modules own invitation tokens and scoped grants. OTP/token hashes and contact are restricted. |
| Individual Profile & Onboarding | Individual owns goals, preferences and staged first run. **IndividualProfile**, **OnboardingProgress**; four valid baselines and offline commitment gate activation. | `OnboardingStageCompleted`; reads Lab completion, not raw partner records. Private by default. |
| Lab | Version/scoring/protocol governance and individual formal attempts. **InstrumentVersion**, **AssessmentAttempt**, **AssessmentWindow**; validity/comparability explicit. | `OfficialAssessmentCompleted`; recovery may consume vetted summary only. Raw answers and task timing are highly restricted. |
| Recovery | User plans future commitments and weekly adaptation. **RecoveryCycle** owns state; **PlanRevision** freezes proposed obligations; **WeeklyReview** records choice. No overwrite of past schedule. | `CycleActivated`, `PlanRevised`, `WeekReviewed`; reads eligible evidence/summary, not a universal score. Private. |
| Activity & Routine | Approved practices, independent per-type levels, attempts and personal self-reports. **PracticeVersion**, **PracticeAttempt**, **OfflineRoutine**; attempt validity and repetition rules. | `PracticeValidated`, `RoutineCheckedIn`; emit provenance to Evidence. Self-report remains labeled. |
| Digital Shield | User configuration, protected sessions and supported-browser usage. **ShieldConfiguration**, **ProtectionSession**, **BrowserUsagePeriod**; no claim beyond consented browser scope. | `ProtectionEnded`, `UsagePeriodAccepted`; limited summaries to Insights. Browsing data strictly private. |
| Institution & Admission | Verified Institution publishes Initiative, reviews applications and holds seats. **Institution**, **Initiative**, **InitiativeApplication**, **InitiativeMembership**, **InitiativeSeat**. Approval locks Initiative/slot; one accepted membership/person; ≤135 slots. | `InitiativePublished`, `ApplicationAccepted`, `MembershipSuspended`; consumes Identity; feeds Explore/Reports. Forms and admissions private to scoped operators. |
| Independent Coach & Groups | Coach owns versioned staged Program; operational **OperationalGroup** belongs to one Initiative or Program; membership/coach assignment/completion history. **CoachProgram**, **OperationalGroup**, **ProgramCompletion**. | `GroupPlaced`, `CoachChanged`, `ProgramCompleted`; Program owner retained through links. Rosters visible only to assigned operators. |
| Shared Assignments | Common tasks for both group kinds. **Assignment**, **Submission**; immutable assignment revisions, recipient snapshot, submission attempts and review decisions. | `AssignmentPublished`, `SubmissionReviewed`; reviewer scope from group owner; only student feedback is student-visible. |
| Sessions & Attendance | Institution sessions optionally linked to an Initiative, mode inventory, registration, factual attendance, excuse and Initiative completion. **Session**, **SessionRegistration**, **SessionAttendance**, **AbsenceExcuse**, **InitiativeCompletion**. | `AttendanceRecorded/Corrected`, `ExcuseDecided`, `InitiativeCompleted`; attendance requires active exact-session Supervisor duty/appointment; no excuse-to-presence rewrite. Restricted excuse files. |
| Provider Experiences | Provider owns experience/camp, capacity, waitlist, attendance and completion. **Experience**, **ExperienceBooking**, **SeatOffer**, **CampCompletion**. Slot allocation under lock; no overbooking. | `SeatOffered/Accepted/Expired`, `CampCompleted`; linked Initiative gets permitted projection only. Safety/contact data narrow. |
| Forms & Competition | Institution-owned identified forms and judged entries. **FormVersion**, **FormResponse**, **Competition**, **CompetitionEntry**. Response pinned to published version and person. | `FormSubmitted`, `ResultPublished`; restricted answers/files; no anonymous Phase-1 path. |
| Supervisor Appointments | Initiative or Provider resource-scoped access. **InitiativeStaffAppointment**, **ProviderStaffAppointment**; revocation ends future authority, history remains. | `AppointmentAccepted/Revoked`; application approval and attendance query fresh active grant. No global Supervisor role. |
| Partnerships | Counterpart acceptance and limited data contract. **ProgramLink**, **ExperienceLink**; links never transfer Program/Experience owner. | `LinkAccepted/Ended`; published projections and reporting honor agreed scope. |
| Community | Finite posts, peer goals and moderation. **Post**, **JointGoal**, **ContentReport**. Engagement has no reward eligibility. | `PostPublished/Moderated`; privacy and rate limits; no raw personal measurement exposure. |
| Platform Governance | Admin verification, catalog/CMS publication and suspension. **VerificationCase**, **ContentRelease**, **GovernanceAction**. One conceptual Admin capability; every action attributed. | `EntityApproved`, `ContentReleased`, `ResourceSuspended`; cannot silently take operational ownership. Sensitive proof restricted. |
| Commercial Entitlements | Versioned plan features and usage, separate from resource authority. **PlanVersion**, **Subscription**, **EntitlementAllocation**. No price/quotas inferred. | `EntitlementChanged`; authorization still checks owner grants. Billing integration postponed. |
| Evidence, Reward & Reporting | Source event registry, unique personal/group reward decisions, corrected ledger and derived projections; reporting uses original records. **EvidenceEvent**, **PersonalRewardEntry**, **GroupRewardEntry**, **ReportSnapshot**. | `RewardGranted/Reversed`; no duplicate source/effect, no false universal recovery score. Source classification accompanies each metric. |
| Notifications & Audit | Durable outbox, recipient notices, idempotency and tamper-evident operational trace. **OutboxMessage**, **Notification**, **AuditEvent**, **IdempotencyRecord**. | Consumes domain events; transactionally records source write/outbox; delivery retry. Audit access is narrow and retention governed. |

## Actors, value objects, lifecycle and command boundaries

Value Objects below are candidate immutable C# types mapped to owned/complex columns where useful; they do not imply additional tables. Every command checks the actor's current resource grant, and the authoritative state plus audit/outbox commit together. Read projections and cross-context consumers run after commit unless a command explicitly requires their source in the same transaction.

| Context | Actors and value objects | Main lifecycle; transaction boundary |
|---|---|---|
| Identity & Access | Person, Admin; `NormalizedEmail`, `CredentialHash`, `ConsentDecision`, `PublicId`. | Email pending→verified→retired; credential active→revoked. Verification/credential rotation and grant revocation each commit once. |
| Individual Profile & Onboarding | Individual; `GoalCode`, `TimeZoneId`, `OnboardingStage`. | Started→Baselines→Preview→Activated; each checkpoint commits, activation checks four valid baselines and offline commitment in one command. |
| Lab | Individual, content Admin; `InstrumentCode`, `ScoringVersion`, `ValidityResult`, `WindowKey`. | Instrument draft→published→retired; attempt started→submitted→valid/invalid. One attempt submission/scoring transaction; official eligibility locked per window. |
| Recovery | Individual; `LocalDate`, `TimeZoneId`, `PolicyVersion`, `PlanChoice`. | Cycle preview→active→review due→reviewed; activation and each accepted future-only revision commit with affected actions. |
| Activity & Routine | Individual, content Admin, reviewing Coach where assigned; `PracticeType`, `DifficultyTier`, `EvidenceTier`. | Definition draft→published; attempt started→completed/invalid; routine active→paused→archived. Validity finalization publishes one source event. |
| Digital Shield | Individual, paired browser extension; `SupportedDomain`, `Coverage`, `ThresholdMinutes`. | Installation paired→revoked; protection active→ended/failed. Config publish and observed period acceptance each have an idempotent transaction. |
| Institution & Admission | Admin, Representative, active Initiative Supervisor, applicant; `Capacity`, `TermsRevision`, `AdmissionDecision`. | Institution applied→verified; Initiative draft→published; Application pending/queued/offered→accepted/rejected/withdrawn. Approval atomically claims a slot and creates membership. |
| Independent Coach & Groups | Approved independent Coach, invited Initiative Coach, Student; `ProgramStageNo`, `PlacementPeriod`, `GroupParent`. | Program draft→published; Group open→closed; membership active→left/completed. Group transfer closes prior placement and opens the new one in one transaction. |
| Shared Assignments | Scoped Coach, Student; `ReviewOutcome`, `DueAtUtc`, `RecipientSnapshot`. | Assignment draft→published; Submission draft→submitted→needs revision→approved/rejected. A review decision pins one attempt and emits evidence in one transaction. |
| Sessions & Attendance | Representative, active exact-session Supervisor, registered Student; `ParticipationMode`, `AttendanceMethod`, `AttendanceFact`. | Registration pending→confirmed→cancelled/completed; fact not recorded→present/late/absent; excuse separately submitted→recommended→accepted/rejected. Each inventory claim/correction is atomic. |
| Provider Experiences | Provider staff, participant, appointed Supervisor; `OfferExpiry`, `SeatNumber`, `CompletionCriterionRef`. | Booking queued→offered→confirmed/declined/expired/cancelled; completion separate. Owner/slot/offer/booking change under one allocation transaction. |
| Forms & Competition | Representative, identified respondent, appointed judge; `QuestionKind`, `CriterionScore`, `ConsentVersion`. | Form draft→published; response draft→submitted/withdrawn; entry submitted→judged→result published. Submit pins version and writes answers atomically. |
| Supervisor Appointments | Representative or Provider owner, invited Supervisor; `ScopedGrant`, `InvitationExpiry`. | Invite pending→accepted/expired/revoked; appointment active→revoked. Acceptance checks email, exact resource and Initiative three-cap in one transaction. |
| Partnerships | Initiative Representative, Program/Experience owner; `LinkScope`, `TermsVersion`. | Requested→accepted→ended; counterpart acceptance commits an immutable owner reference and permitted data scope. |
| Community | Member, moderator; `ModerationReason`, `GoalTargetDate`. | Post draft→published→hidden/removed; report submitted→resolved; goal active→closed. Moderation action and decision history commit together. |
| Platform Governance | Admin, content publisher; `PublicationVersion`, `GovernanceReason`. | Verification submitted→approved/rejected; release draft→published→superseded. Approval/publication records actor and release version atomically. |
| Commercial Entitlements | Payer, Admin, entitlement service; `FeatureCode`, `UsagePeriod`, `MoneyDisclosure`. | Plan version published; subscription proposed→active→expired/cancelled. Usage reservation locks allocation and appends one source-keyed ledger entry; charging awaits approved policy. |
| Evidence, Reward & Reporting | Source owner, reward worker, scoped report reader; `Provenance`, `EffectCode`, `PolicyVersion`, `ReportPeriod`. | Evidence accepted→invalidated; grant→reversed; projection rebuilt from ledger. Unique source/effect grant is committed per reward evaluation; reports read consistent source watermarks. |
| Notifications & Audit | Domain command actor, worker, auditor; `CorrelationId`, `DeliveryOutcome`, `IdempotencyKey`. | Outbox pending→delivered/dead letter; notification pending→ready→read. Source command commits outbox/audit; delivery attempts retry independently. |

**Why these roots:** Person changes do not lock all memberships; Initiative is the admission capacity lock, while its application and membership retain independent histories. A Group is the assignment authorization unit; Assignment/Submission each need their own revision transition, so they are separate roots. A Booking/Offer needs atomic capacity reservation but need not load all Experience sessions. Evidence and reward ledgers are separate from the visual projection to allow corrections. No aggregate contains a person's entire life across workspaces.
