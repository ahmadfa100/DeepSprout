These are **design walkthroughs**, not executed SQL tests. `T` denotes one SQL transaction. Each row names the source tables, state/event, race/failure, and required test. A failed validation commits nothing; outbox delivery failures do not undo a committed fact. See [11](11-transactions-and-concurrency.md) for locks.

## Cross-scenario acceptance checklist

Every state-changing API returns original public IDs and current version; repeated idempotency key returns the prior result or conflict on mismatched request hash. No scenario requires duplicate person, application, booking or reward rows. Accepted seats and active Supervisors are scoped **per Initiative**. Operational caps are separate from unapproved subscription quotas. Historical published revisions and source provenance remain queryable. Reports state denominator/coverage; no Lab/Shield/Recovery improvement is inferred from partner attendance or completion. These checks close the major architecture questions, subject to the open policy decisions in [15](15-open-questions-and-risks.md).
