# 05 — Entity catalog

The [data dictionary](07-database-schema.md) enumerates every physical table and its columns. This catalog groups their business meaning; statuses are explicit state machines, not table names. `Root` means commands own a consistency boundary there; `history` is append-only after publication.

| Owner | Roots and entities | Lifecycle and relationship |
|---|---|---|
| Identity | `Person` root; `PersonEmail`, `PasswordCredential`, `OtpChallenge`, `GlobalGrant`, `ConsentRecord` | Person active/suspended; email verified before matching owner-specific invites; credential hash never logged. Invitation consumed once, then creates owner grant; consent decisions retain versions. |
| Individual | `IndividualProfile`, `OnboardingProgress` roots | Optional profile tied 1:1 to Person; first-run stages resume, upgrade adds profile without rekeying. |
| Lab | `AssessmentInstrument`, `InstrumentVersion`, `AssessmentWindow`, `AssessmentAttempt`, `AssessmentResponse`, `AssessmentScore` | Draft/published/retired instrument version; attempt started/partial/completed/invalid; score is tied to scoring version. |
| Recovery | `RecoveryJourney`, `RecoveryCycle`, `PlanRevision`, `ScheduledAction`, `WeeklyReview` | Journey spans cycles; cycle preview/active/reviewed/closed; revisions apply only to future actions. |
| Activity | `PracticeDefinition`, `PracticeVersion`, `PracticeAttempt`, `PracticeProgressionDecision`, `OfflineRoutine`, `RoutineCheckIn` | Published definition versions; attempt validity; per-type progression; routine paused/active and check-in self-report. |
| Shield | `ExtensionInstallation`, `ShieldConfiguration`, `ShieldSelectedDomain`, `ProtectionSession`, `BrowserUsagePeriod`, `BrowserUsageDomain` | Paired/revoked install; versioned selected-site config; session active/ended/failed; per-domain observation and coverage gaps explicit. |
| Institution | `Institution`, `InstitutionVerificationCase`, `RepresentativeMembership`, `Initiative`, `InitiativeRevision`, `InitiativeContent`, `InitiativeApplication`, `InitiativeSeatOffer`, `InitiativeSeat`, `InitiativeMembership`, `InitiativeStaffInvitation`, `InitiativeStaffAppointment` | Verification gates publish; versioned awareness content; application/offer/accepted membership separate; seat is capacity authority; appointment active/revoked distinct from invite. |
| Coach/groups | `CoachApproval`, `CoachProgram`, `ProgramRevision`, `ProgramStage`, `OperationalGroup`, `InitiativeGroupPlacement`, `ProgramGroupMembership`, `ProgramCompletion`, `GroupCoachAssignment`, `ProgramGroupInvitation` | Independent Coach approval vs invited Initiative Coach; group XOR owner; staged pathway, placement/handover and completion history retained. |
| Assignments | `Assignment`, `AssignmentRevision`, `AssignmentRecipient`, `Submission`, `SubmissionAttempt`, `ReviewDecision`, `ReviewPrivateNote`, `CoachReport`, `SupervisorReport` | Shared engine; recipient snapshotted; resubmissions and review authors immutable; reports derived from originals. |
| Sessions | `Session`, `SessionRevision`, `InitiativeSessionDuty`, `StandaloneSessionSupervisorAppointment`, `SessionCapacityPool`, `SessionSeat`, `SessionRegistration`, `SessionAttendance`, `AttendanceCorrection`, `AbsenceExcuse`, `InitiativeCompletion` | Institution Session may be linked to Initiative or stand alone; scoped Supervisor duty, mode booking, fact, excuse and completion remain independent. |
| Provider | `Provider`, `ProviderVerificationCase`, `ProviderMembership`, `Experience`, `ExperienceRevision`, `ExperienceSession`, `ExperienceSeat`, `ExperienceBooking`, `SeatOffer`, `ProviderStaffInvitation`, `ProviderStaffAppointment`, `ProviderAppointmentSession`, `ProviderCohort`, `ProviderCohortMember`, `ProviderAttendance`, `ProviderAttendanceCorrection`, `CampCompletion`, `ProviderIncident` | Provider keeps owner; held/occupied/free slots; offer expiry and reoffer; camp completion uses criteria, not mere QR; safety report is restricted. |
| Forms/competition | `Form`, `FormVersion`, `FormQuestion`, `FormQuestionOption`, `FormResponse`, `FormAnswer`, `FormAnswerChoice`, `SecureFile`, `Competition`, `CompetitionCriterion`, `CompetitionEntry`, `CompetitionJudgment`, `CompetitionCriterionScore` | Identified response pinned to version; restricted files; judges and result publication. |
| Partnership | `ProgramLink`, `ExperienceLink` | Requested/accepted/ended; original resource IDs and owner preserved. |
| Community | `Post`, `Comment`, `Reaction`, `Bookmark`, `ContentReport`, `ModerationDecision`, `JointGoal`, `JointGoalMember`, `JointGoalCheckIn` | Finite feed, report/decision history, no social rewards. |
| Governance/commercial | `ContentRelease`, `GovernanceAction`, `PlanVersion`, `PlanFeature`, `Subscription`, `EntitlementAllocation`, `UsageLedger` | Versioned publish/rollback, audited governance, proposed commercial capabilities without assumed prices. |
| Evidence/operations | `EvidenceEvent`, `RewardPolicyVersion`, `PersonalRewardEntry`, `GroupRewardEntry`, `PersonalGardenState`, `PersonalGardenSummary`, `GroupGarden`, `GroupGardenState`, `ReportSnapshot`, `AuditEvent`, `OutboxMessage`, `Notification`, `DeliveryAttempt`, `IdempotencyRecord` | Source-backed entries and compensations; derived, rebuildable scene/report states; durable notices and retries. |

The catalog is broad because the approved product spans several independent lifecycles. Each listed table either preserves an approved fact/history or supports a specific integrity/security requirement. Optional detail such as payment transactions, AI prompts, generic EAV fields and anonymous-survey identities is deliberately absent pending product decisions.
