# 07 — Proposed SQL Server data dictionary

**Design status:** logical/physical proposal, not executed DDL. A table is included only for an approved capability or a justified security/integrity concern. `!` means `NOT NULL`, `?` means nullable. `→` names a foreign key. Unless a row says otherwise, every table has `Id bigint IDENTITY(1,1) PK` clustered; outward-facing roots also have `PublicId uniqueidentifier!` unique nonclustered, generated by the API. Every mutable row has `CreatedAtUtc datetime2(3)!`, `UpdatedAtUtc datetime2(3)!`, `RowVersion rowversion!`; append-only/history rows have `CreatedAtUtc datetime2(3)!` and no mutable update. Actor/time/reason details go to `ops.AuditEvent` in the **same transaction**. All FKs are `NO ACTION` for historical/published parents. Limited prepublication draft cleanup is a governed service operation. All FK columns are indexed when a query joins or filters through them; named composite indexes below show the business access path. Do not store raw file bytes, tokens or passwords in these tables.

**Classes:** `M` mutable root/state (rowversion and audit); `H` append-only fact/history (correction by new row); `V` immutable published version; `P` rebuildable projection. Privacy `U` public projection, `O` scoped operational, `S` private personal/sensitive, `R` restricted secret/file/assessment/browser, `I` internal admin. One-to-many is the default cardinality for FKs; `1:1`/junction uniqueness is called out. `UQ` unique index/constraint, `UXF` filtered unique index, `CK` check, `IX` read index. Codes are `nvarchar(32)` with named `CK` allowed values or versioned lookup where policy evolves; no CLR ordinal persistence. All dates are UTC instants unless named `LocalDate`/time zone. Lifecycle text names the meaningful states; state machine details are in [critical workflows](diagrams/critical-workflows.md). The owner prefix is a SQL schema, not a separate database.

**Exact implicit `PublicId` set:** `Person`, `AssessmentAttempt`, `RecoveryCycle`, `PracticeAttempt`, `Institution`, `Initiative`, `InitiativeApplication`, `InitiativeSeatOffer`, `InitiativeMembership`, `CoachProgram`, `OperationalGroup`, `Assignment`, `Submission`, `Session`, `SessionRegistration`, `AbsenceExcuse`, `Provider`, `Experience`, `ExperienceBooking`, `SeatOffer`, `ProviderIncident`, `Form`, `FormResponse`, `Competition`, `CompetitionEntry`, `ProgramLink`, `ExperienceLink`, `Post`, `JointGoal`, and `Notification`. These tables receive the common unique immutable `PublicId`; other tables remain internal and are reached through a parent public ID or an explicitly named token. `EvidenceEvent.EventPublicId` and `ExtensionInstallation.InstallationPublicId` are their explicit stable identifiers. This list defines the convention used by the rows below; it is not a new role or permission grant.

## Dictionary review notes

The `CurrentRevisionId` pointers on roots and their immutable child revision FKs form a deliberate two-step insert/update mapping. Configure `NO ACTION` and explicit EF migrations; avoid cascade cycles. Where a source `EvidenceEventId` is optional, absence means no reward evaluation has been published, not evidence of zero. `PersonalGardenState` holds only per-type stages; `PersonalGardenSummary` holds decoration counts once. Every status transition also writes `AuditEvent`; sensitive file/assessment/browsing reads add an access audit. Tables marked `P` may be rebuilt from originals; no report cache grants a new permission. The few XOR union tables (`GroupGarden`, `Subscription`, `EntitlementAllocation`, `ContentReport`) have a **closed, documented set of FKs** and checks; they are not arbitrary polymorphic resource stores.
